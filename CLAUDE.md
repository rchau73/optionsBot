## Environment & config

Strict separation — do not mix:
- `.env` — Deribit platform only: credentials, `DERIBIT_ENV` (testnet|live), rate limits (two pools), retry/backoff, circuit breaker, heartbeat/reconnect.
- `config_*.yaml` — all strategy and execution logic. `config.Load` fills defaults and runs `Validate()`; `RequireCredentials()` is called only for trading, so backtests need no API key.

Never reintroduce env-var overrides for logic parameters.

**Two local environments, sharing nothing** (2026-10-17, #129; `docs/operations.md` "Environments"): `~/dev/go/optionsBot-env/stable` (a release tag, moved only by `scripts/promote.sh`, the track record, market recorder on) and `~/dev/go/optionsBot-env/mvp` (main, auto-deployed by `deploy.sh`; the agents run from it). Each clone has its own `.env` — **its own Deribit account**: a bot cancels every order of its currency at startup and adopts every short it finds, so two environments on one account fight — and a `deploy.env` (`OPTIONSBOT_ENV`, `MONITOR_PORT` 3000/3100, `BOT_RECORD_MARKET`; mvp also `BOT_CONFIG_BTC=./config_btc.mvp.yaml` — BTC on `gex_direction: sma` while stable stays on `bias`, to compare the two, #168; that file is `config_btc.yaml` with only that line different, enforced by `TestConfig_MVPBTCDiffersOnlyInDirection`: change both). `scripts/env_lib.sh` `env_check` refuses a shared `DERIBIT_CLIENT_ID` or port; compose refuses without `OPTIONSBOT_ENV`. Bots report `deployment`/`version` (`BOT_DEPLOYMENT`/`BOT_VERSION`) in `/api/status`, shown in the monitor header. The dev checkout runs nothing; `data/btc` there links to stable's for the research tools. The monitor requires a signed-in session on every page and `/api` route (#170, `frontend/README.md` "Sign-in"; users per environment, `AUTH_SECRET` in its `.env` or it won't start); scripts that read it (`wait_healthy`, the agents, `stress_inputs.sh`) send that environment's read-only `MONITOR_API_TOKEN` (`env_monitor_token`) — a new script reading the monitor must too.

**Few settings** (2026-10-14, the user's call: "far complex to manage"): the YAML holds only what is tuned — slots, exits, `repair_cooldown_hours`, `gamma_flip_buffer_sd`, `gex_direction`, margin bands/MM, `max_leg_size_multiple`, `min_premium`. Every other rule value is fixed in `internal/config/fixed.go` (`ApplyFixed`, run by `Load`); a file that sets a fixed key fails to load (`fixedKeys`). The snake_case names below (e.g. `gex_shed_confirm_snapshots` (2)) name those fixed values — the Go fields keep them, so tests and sweeps can still vary them in code. Do not add a config key for a new rule: fix its value in `fixed.go` and keep a `cmd/stress` flag to study it. `tests/config_effective_test.go` pins every effective setting of both shipped configs (golden `tests/testdata/effective_config_*.json`; regenerate with `UPDATE_GOLDEN=1` only for an intended change).

**Secrets never reach GitHub** (the repository is public): `.env` and every `.env.*` except `.env.example` are ignored; `make hooks` installs `.githooks/pre-commit`, which refuses env/key files and any staged line containing a value of a `*SECRET*`/`*TOKEN*`/`*CLIENT_ID*`/`*KEY*` variable from the local `.env`; CI runs gitleaks over the full history. Never paste a secret into a commit, PR text, test fixture or log line.

## Architecture

`cmd/bot/main.go` is the composition root: it wires `Gateway → MarketData → GEX Manager → Strategy` (plus, on testnet, a public-only mainnet gateway for GEX — see `internal/gex`), handles `SIGUSR1` (kill switch) and watches `Gateway.Fatal()`. Details: `docs/architecture.md`; diagrams: `docs/README.md`.

- **`internal/gateway`** — every Deribit connection goes through it. `PublicOnly()` gateways never authenticate and refuse `private/*` (`ErrPrivateOnPublic`); `WithName` tags their logs (`gateway=trading|mainnet-public`). `Call` → priority queue (high lane first) → rate limiter (matching-engine pool for buy/sell/edit/cancel, non-matching pool otherwise) → circuit breaker (skipped for high priority) → socket. One writer goroutine never waits for replies; `readLoop` routes replies by request ID. Every request gets exactly one answer (reply, RPC error, timeout, `ErrConnectionLost`, `ErrCircuitOpen`). Retries only for idempotent methods (`public/*`, `private/get_*`) — never for orders. Breaker counts transport failures and exchange-health errors only. Callers also hold a hard deadline, so a request that is never sent still times out. Reconnect runs on the root context; a drop during a reconnect re-arms it (never ignored) and a failed subscription restore is a failed attempt; giving up is reported via `Fatal()`. `main` also runs a decision-loop watchdog (`strategy.WatchProgress`): no cycle for max(10 × eval interval, 10 min) → exit for a supervised restart (never when halted by the kill switch).
- **`internal/marketdata`** — option chain, subscriptions to the index, DVOL (`deribit_volatility_index.btc_usd`) and tickers of tradable expiries only: every expiry a slot could take — its `ExpiryWindow` and the stretch up to `StretchHi` — the same ranges `marketdata.PickExpiry` uses. Valid ticker intervals are `100ms` and `raw` only. `DVOLTracker` keeps one value per UTC day. Readers get copies. `Track(ctx, names)` subscribes to the tickers of held instruments outside those expiries (positions loaded at startup); the strategy calls it every cycle. `Instrument.HasQuote()` is false until the first ticker: never use such an instrument's zero prices as a mark.
- **`internal/gex`** — every 60 s computes dealer gamma exposure from **mainnet** open interest (always: testnet prices mirror mainnet but its open interest belongs to test accounts, so testnet GEX describes nothing real). `gex.Build(rows, now, params)` is pure; `gex_method: script` (default) reproduces GestaoCarteira's `deribit_tc_export_v3.py` exactly (5 nearest expiries of the chain, strikes ±`gex_strike_range_pct` of each expiry's future, regime = sign of the weighted sum, flip = lowest crossing, no hysteresis) — `tests/gex_parity_test.go` checks it against the script's own output on captured mainnet data; `nearest_flip` is the original rule (crossing nearest spot, regime = spot vs flip, hysteresis `gamma_regime_band_pct`). Option names are parsed with `marketdata.ParseOptionName` (daily expiries have one-digit days, e.g. `4OCT26`).
- **`internal/strategy`** — the decision loop; depends only on the interfaces in `deps.go`.
  - `strategy.go` Run/evaluate/heartbeat · `limits.go` margin policy (status, MM reduction, simulation sizing) · `open.go` entry · `pending.go` fill tracking · `close.go` `buyToClose`, rollouts, GEX closes · `repair.go` · `reconcile.go` · `rebalance.go` · `killswitch.go`.
  - Pure rules shared with the backtest: `entry.go` (`SelectExpiry(…, now, …)`, `SelectSlotExpiry`, `SelectStrike`, `SelectStrikePair`), `rollout.go` (`EvaluateLeg(pos, now, …)`), `gamma.go`, `margin.go`, `pricing.go` (`StepDownPrice`, `FloorPrice`).
- **`internal/orders`** — `Executor` (Deribit calls behind `rpcCaller`; `ErrForbidden`; order `label`), `StateManager` (in-memory book; readers get snapshots; greeks short-signed), decision journal `orders.log` (`journal.go` types: `EventContext`, `MarketSnapshot`, `OrderLog`, `PnLRecord`), price/lot helpers.
- **Journal rule:** every decision (submit, amend, cancel, fill, close, reconcile, skip) is journaled through `s.eventContext`/`s.instrumentContext`, which build the market snapshot (`strategy/snapshot.go`, pure `BuildMarketSnapshot`). Realised P&L is booked per slot in `buyToClose`, **net of fees** (`orders.ClosedNetPnL`: premium − buy-back − the position's share of its opening fees − the closing fee); `Position.Fees` holds the opening fees (read from Deribit with `OrderFee` when a fill is booked) and unrealised P&L is `NetPnL()`. The exit rules keep using the gross premium. The backtest charges Deribit's fee (`orders.OptionFee`: 0.03 % of the underlying, capped at 12.5 % of the price) and reports net trades; `strategy/pnl.go` writes periodic P&L lines. New decision points must journal too, and every close passes a `detail` (the rule and its numbers, e.g. `RolloutDecision.Detail`) to `buyToClose`.
- **The journal is the history:** at startup `main` replays `orders.log` (`orders.ReplayFile`, fast path: only fills/closes are decoded) and restores realised P&L per slot (`Strategy.RestorePnL`), event counts, the last 500 events and every open/close (`Logger.Restore`, served at `/api/trades`), so nothing the monitor shows resets on restart. Realised P&L has one source (the journal's closes); `history.Store` records it as given and adds nothing. `--reset-history` archives `orders.log` and `data/pnl_history.jsonl` to `data/archive/<time>/` and exits — never delete history.
- **`internal/api`** — read-only monitor API (`BOT_API_ADDR`): `/api/status|positions|orders|pnl|events`, built from `Strategy.View()` (`held_legs`: each missing leg and what holds its repair — `holds.go`, `repairGate` is the one gate chain repair and the view share; `flip_buffer_pct` is the live shed buffer, `GammaMonitor.FlipBuffer`, so the monitor's flip ±1σ band is the one the shed uses; `sma` is the SMA trend's levels, `GammaMonitor.SMALevels` — SMA9, SMA21, swings with their days, the trend and the `SMATrendOf` reason; a change of the SMA trend is journaled once as `trend_changed` (`trend.go`, #118); loop-published snapshots, never calls Deribit) and the journal's in-memory recent events; `connections.<gateway>` in `/api/status` is each gateway's `ConnStats` (drops, reconnects, timeouts today; last drop time and error — `api.WithConnection`, #87). The state-changing routes are `POST /api/positions/close` (manual close, below: testnet only) and `POST /api/rebalance` (manual rebalance, below: live and testnet): bearer `BOT_ADMIN_TOKEN`, audited in the bot log and journaled; the monitor's server-side proxies add the token and refuse cross-origin requests. Never add other endpoints that change trading state without auth + confirmation + audit. `cmd/monitor-demo` serves it with simulated data. `/api/account` serves `internal/account` (cached `private/get_account_summaries` plus `private/get_positions` for each held currency, all kinds — so positions no bot manages, which still use margin, are visible; polled every `BOT_ACCOUNT_POLL_SEC`; margin figures are Deribit's, never recomputed). The strategy itself reads only short options. `/api/pnl/history?range=` serves `internal/history` (append-only `data/pnl_history.jsonl`, written by `strategy/pnl.go` each report interval; trading never reads it). Each line also carries the margin view the policy used (`im_pct`, `im_limit_pct`, `mm_pct`, `entries_allowed` — false while frozen, MM-blocked, GEX-stale, stop-deferred or margin unknown; `strategy.HistoryMargin` from `RiskView`, `marginState.entriesAllowed`; old lines without them still load); pure `history.Utilisation` is the time-weighted mean of IM ÷ limit while entries were allowed plus the allowed share (a line stands for ≤ `MaxSampleGap` 15 min), served as `utilisation_7d`/`utilisation_30d` in `/api/status` (#174, E1's metric). `/api/summary` (`summary.go`, pure `BuildSummary`, #177) is the investor's four answers from the view and the journal's trades: `holding`, `income` (realised net P&L per UTC month, last 6, from the journal's closes — its one source — plus unrealised), `worst_case` (a labelled model: Black–Scholes on each leg's IV, a one-day ±3 daily σ move from DVOL, loss in coin, USD and % of equity) and `last_action` (latest open/close, `PlainReason` maps its journal reason to plain words; a new close reason needs a line there); fields in `frontend/README.md`.
- **`internal/hedge`** — writes `hedge_report.json` when |net delta| ≥ threshold. **Never places orders.**
- **`internal/recorder`** — market history for backtests and stress tests: every `market_record_minutes` (60) it writes the GEX manager's last mainnet book summary (`LatestSummary`, no extra Deribit call) with Black–Scholes greeks to `data/market/YYYY-MM-DD.csv.gz` (gzip member per snapshot); `LinearBook` writes the coin's USDC-settled options (one extra mainnet call, fetched just before each snapshot — the `Fetcher` interface; the GEX manager is never one) to `data/market_usdc/`, to compare liquidity; `GEXRecorder` (`gexminute.go`, #122) writes every GEX snapshot (one a minute: flip, regime, median flip, GEX sum, DVOL, flip buffer — no Deribit call) as a JSON line to `data/market_gex/YYYY-MM-DD.jsonl.gz`, read by `ReadGEXDir`. Never touches trading; not archived by `--reset-history`.
- **`internal/backtest`** — CSV feed, `SimExecutor`, day-loop `Engine` using the pure rules at the simulated date, sweep (scenarios applied as slot matrices), ladder sweep (`ladder.go`: DTE ladders with/without weeklies → slot occupancy from `occupancy.go`, return on margin, worst week), walk-forward. As live, a DTE roll only closes (the slot re-enters); other exits are repaired on the same strangle and expiry.
- **`cmd/stress`** — research tool, not the bot: replays the live book (snapshot from `scripts/stress_inputs.sh`) through scripted shocks with the bot's pure rules and modelled prices/fills/fees. Keep its defaults equal to today's bot when a rule changes, and re-run it to compare rule changes on the same paths. Its trend is the bot's own (`strategy.SMALevelsOf`, which `GammaMonitor.SMALevels`/`detectTrend` call — swings included). `-replay <data/market dir>` (`internal/replay`, reader `recorder.ReadDir`) runs the bot's pure rules and its `GammaMonitor` (`PushPriceAt`) hour by hour on the recorded mainnet books: GEX rebuilt with `gex.Build`, fills at the recorded bid/ask/mid by the bot's price floors, margin modelled; where minute GEX records exist (`-gex`, default `market_gex` beside the books; `none` = hourly) it decides at each record on the last hourly book's prices (`replay/ticks.go`), hourly where they are absent; `-journal` prints the bot's actual P&L over the window to measure the gap. Not modelled there: rebalance, leg balancing, churn breaker, journal-restored holds.

### Trading rules (keep these true)

- **Slots:** each `(DTE, delta)` in `dte_delta_matrix` is one strangle slot; occupied by an open strangle (even one-legged) or a pending entry.
- **Margin policy** (`internal/risk`, pure; applied in `strategy/limits.go`): every figure is Deribit's — account-wide USD totals under cross collateral, else the currency's own (`AccountSummary.MarginUsage`). IM limit (% of margin balance) = band of the DVOL IV percentile (`iv_margin_bands`), or the lowest band under a confirmed negative gamma regime. Band/regime changes are confirmed on `iv_band_confirm_days` consecutive UTC daily closes (DVOL closes from `DVOLTracker.Daily`, regime closes from `data/regime_history.jsonl`; a **brand-new** bot — empty regime history — seeds the `iv_band_confirm_days` closes before today with the live regime, marked `seeded`, journaled `regime_seeded` (`RegimeStore.Seed`, #147: a fresh mvp sat frozen a day), so it starts from the market as it is; restarts are never seeded); until then new risk is frozen (exits, rolls and repairs continue) — but only when confirming the change would lower the effective limit (`limitFor` in `risk.Evaluate`): a change that can only raise it or leave it (a DVOL band rise, a DVOL change under a confirmed negative regime, the regime turning positive) stays `pending` without freezing — the current, stricter limit applies until it confirms; the regime turning negative always freezes (2026-10-15: ETH frozen and flat for days on a DVOL change that could not lift its pinned 20 %; 2026-10-16 ETH frozen ~8 h of 12 by a live regime flapping to positive, #105). A confirmed limit change (and startup) runs `rebalancePositions` toward it, sizing each slot as a whole (all its strangles) — except that the first pass after a startup does nothing while IM is within `rebalance_startup_band_pct` (±1.5 pp) of the limit (`RebalanceInBand`, journaled `rebalance_in_band`; 2026-10-17 BTC: two deploys 38 min apart cut and re-sold 1.2 lots, #123), a later confirmed change is met exactly; a complement that times out short re-arms it after `rebalance_retry_minutes` (journaled `rebalance_retry`) — doubled per unfilled pass from the `rebalance_backoff_after` (3)-th pass in a row whose every complement ran to its fill timeout with no fill, up to `rebalance_retry_max_minutes` (60), reset by any fill or a limit change (`RebalanceRetryWait`, `NextUnfilledPasses`; 2026-10-14 BTC: 12 unfilled top-up orders in 1.5 h) — complements the bot cancels itself (freeze, shed, kill switch) don't count, a held or failed top-up re-arms at the base wait, the kill switch never re-arms (#93) — never while a complement or an entry is still working (#97: one new-risk sizer at a time — a due pass waits for a working entry, journaled once as a `rebalance_wait_entry` skip, and entries wait for a working complement, `entry_wait_topup`; 2026-10-15 BTC: an entry and a top-up sized together reached IM 25.7 % of 20 % and were bought back); MM ≥ `max_mm_pct` reduces positions at market at once and blocks repairs and entries. IM more than `rebalance_startup_band_pct` over the limit with no rebalance pass this cycle (a transfer out, a price move) is **alert only** (`imalert.go`, pure `IMOverLimitNext`; the product owner's option B on #166): one `im_over_limit` risk line + WARN per episode (IM, limit, `margin_balance` and `ref_margin_balance` = the balance at the last rebalance or confirmed limit change), `risk.im_over_limit(_since)` in `/api/status` and a badge beside the monitor's Rebalance button, `im_over_limit_cleared` once IM is at or under the limit; never an order, never a rebalance (auto-downsize, option C, was rejected without a stress study); in memory, so a restart mid-episode journals it once more. Missing/stale margin data or a failed simulation → no new risk. Never reintroduce a margin cap computed from equity. A freeze or an MM breach also cancels working entries and top-ups (`cancelNewRisk`, journaled `risk_frozen`; repairs keep working) — an order sent just before a freeze otherwise filled into it (2026-10-08).
- **Size cap:** a new leg (entry or complement upsize) is at most `max_leg_size_multiple` (2) × its slot's **normal size** = slot share ÷ the strangle's margin per lot **on its own** (`SimulateAlone`, `add_positions=false`) — `CapLots`. Portfolio margin can price a leg almost free when it offsets the book; the offset disappears when the rest of the book is closed.
- **Sizing:** each vacant slot gets `EntryShare` = min(its slot share = limit × margin balance ÷ all slots, headroom ÷ vacant slots) — the same slot share the rebalance targets, so a strangle opened into a nearly full book is not oversized; `private/simulate_portfolio` (≤ 1 call/s, spaced in the executor) prices one lot, then confirms the final size keeps post-trade IM and MM within the limits. The backtest has no simulator: `backtest.ApproxIMLimitPct` (premium as margin, DVOL band only) is a labelled approximation.
- **Entry:** limit sell at `max(mid, ask)`; premium floor checked for every leg before any order, at the lowest price the step-down can reach; while resting, `repriceLegs` steps the price down (`StepDownPrice`, pure): ask for the first third of the timeout, mid (rounded up to a tick) for the second, then the floor — `entry_price_floor` (mid; also rebalance upsizes) or `repair_price_floor` (bid: a repair restores a one-sided hedge, so it crosses the spread); no bid → stays at the ask; re-pricing up to a higher ask counts toward `order_max_adjustments`; after `order_fill_timeout_sec` cancel, read back the final fill and **book filled legs** (one-legged strangles are completed by repair).
- **Marks:** `refreshMarks` copies a quote onto a position only when the instrument `HasQuote()`, which sets `Position.MarkLive`; otherwise the last known mark stays (from the exchange at reconcile). Reconcile converts Deribit's size-weighted position greeks to per-option greeks (`PerOptionGreeks`).
- **Exit priority** (`EvaluateLeg`): stop-loss → DTE roll → **delta exit** → delta drift → ROI take-profit. The delta exit closes a short leg whose |Δ| reaches `delta_exit_threshold` (0.30) — the move is real — before the 2× stop. Delta exit, drift and take-profit act only on a `MarkLive` position; stop-loss and the DTE roll always act (on the last known mark). Stop-loss = market buy, high priority — except while the leg's book is empty: `StopDeferReason` (`stopguard.go`, pure) defers it while the ask is more than `stop_spread_guard_pct` (20) above the mid (or there is no bid), re-checked each cycle (fires once the spread is normal if the stop still applies, dropped if the price came back), at most `stop_spread_max_wait_minutes` (5), then at market; journaled once as a `stop_deferred` skip; while any stop waits, no entries, top-ups or repairs. The MM cut never waits (stress: deferring it ran margin past liquidation). Rolls = IOC limit at the ask. `buyToClose` books partial fills and keeps the remainder tracked.
- **Unknown order outcomes:** a submit that fails without a Deribit answer (`orders.MaybePlaced`: connection lost, timeout) may still be on the book. Every order has a unique label (`uniqueOrderLabel`); such an order is cancelled by label (`private/cancel_by_label`) each cycle until that succeeds, and its slot (entries/repairs) and instrument (closes) are blocked meanwhile. Every cycle `checkPositions` compares the exchange's short positions with the book (+ fills of tracked entry orders): a difference on two consecutive cycles (or right after resolving an unknown order) is adopted into the book — ERROR log + `reconciled` journal line — so every exchange position is managed. See `strategy/orphans.go`. Never treat a submit error as "not placed" without this.
- **Position safety** (`safety.go`, after the 2026-10-06 testnet churn): the position check compares the exchange with the **sum** of the book's positions per instrument (one instrument can back several positions), and a difference is applied newest position first. A buy-back never exceeds the short the exchange holds this cycle (`capToExchange`), so a wrong book cannot flip a position long. A long on an instrument the bot trades (book, working orders, past buy-backs) is sold at the bid (`close_long`); other longs are left alone. Churn breaker: a slot that buys back and re-sells `churn_max_round_trips` (3) times within `churn_window_minutes` (60) is paused for the window — no entries, repairs, upsizes or leg balancing; exits run.
- **Even legs:** every cycle `balanceStrangles` (`balance.go`) buys back the excess of the larger leg of any strangle whose call and put differ by ≥ 1 lot (IOC at the ask, `rebalance_legs`), outside the rollout window, when no repair is working, and not while an exit rule is closing the smaller leg (a roll filling in pieces: 2026-10-08 ETH shrank 503 → 303). Risk-reducing, so it runs while frozen. One-legged strangles stay with repair.
- **Rollouts only close.** Repair reopens a single rolled leg (same expiry, entry delta, size); a strangle with both legs gone frees its slot for a fresh entry. Never add a second reopen path.
- **No re-selling into the move:** a leg closed by a stop-loss or a delta exit (or cut to zero by the MM limit) is recorded (`stopped.go`) and repaired only when `RepairBlockReason` is empty — entries not frozen, confirmed gamma regime not negative, and `repair_cooldown_hours` (72) since the stop. Rolled (take-profit / delta-drift) legs reopen at once. Held repairs are journaled as `repair_held` skips. The rebalance top-up obeys the same record: it sells nothing into a slot while one of its strangles' stopped (or hand-closed) legs is held (`slotStopHold`, `repair_held: top-up held`), and it tops up only strangles whose two legs are both in the book (`liveLegs`) — a closed leg stays linked to its strangle with its last size, and reading the link topped up a strangle whose put had been closed by hand (2026-10-11 BTC). The records live in memory and are rebuilt at startup from the journal (`StopsFromTrades` → `RestoreStops`, applied after reconcile; a replayed close carries the journal's `close_reason` label — `stop_loss`, not `stop_loss_200pct` — so `closeReasons` matches both: until 2026-10-14 a stop-loss was never restored): a side whose latest close on an expiry was a stop-loss, delta exit, manual close or MM cut, with no repair re-sale since, is held again with its original time, so the cooldown runs on (2026-10-11: a deploy forgot BTC's two hand-closed puts).
- **Confirmed negative regime, side by trend** (`regimeside.go`, pure `RegimeSideBlockReason`): under a confirmed negative gamma regime, no new puts in a bear trend and no new calls in a bull trend (`GammaDecision.TrendDir`) — entries open the other leg alone, repairs of that side are held (`repair_held`), and a top-up adds both sides or none (held as `regime_side`, `rearmRebalance` retries it). Its confirmation lifted the freeze and ETH topped up puts in a bear trend (2026-10-09). Stress: blocking all new risk instead cost ETH 21–27 %; this rule +0.4–1.8 % ETH, +20–24 % BTC.
- **GEX gating:** trading decisions use `GammaDecision.Action`, never raw `gamma.Trend()`. Entry and repair skip a leg only when the action sheds that leg type. A leg is shed only when spot is more than `gamma_flip_buffer_sd` (1.5 since 2026-10-14; was 1) daily standard deviations — `FlipBufferPct` = sd × DVOL ÷ √365, from the live DVOL — below the flip, in a NEGATIVE regime, with a trend (bull → calls, bear → puts). The buffer scales with the asset's volatility (stress 2026-10-14, 1.5 vs 1: BTC on bias +21.5 % today / −1.2 % general, ETH on sma +8.1 % / −0.8 %, fewer sheds in every setup; live replay BTC 7 → 3 sheds); without a DVOL reading it is 0 (shed as before, never less). `Action` is the live signal (entry and repair skip that leg type); the shed itself uses `Shed`, the same action once it has held on `gex_shed_confirm_snapshots` (2) consecutive GEX snapshots (counted by `ComputedAt`, so cycles on one snapshot count once). A shed leg is anchored (`shed.go`, `ShedAnchor`: the flip and buffer at the shed) and repaired only when `ShedRepairBlockReason` is empty — spot above that flip × (1 + buffer) on `gex_repair_confirm_snapshots` (2) consecutive snapshots, or the live regime non-negative for `gex_repair_release_hours` (24) — never because the live flip jumped under spot (2026-10-06 ETH: flip 2697 → 2440 in a minute, puts shed and re-sold). Anchors are in memory like `stopped` and rebuilt from the journal the same way (`ShedsFromTrades` → `applyJournalSheds`: a side whose latest close on an expiry was a GEX shed, with no repair since, is anchored again at the shed's time, `market.gamma_flip` and `market.flip_buffer_pct` — older records without the buffer take today's sd at the shed's DVOL); 2026-10-14 a deploy 20 min after a bias shed re-sold BTC's put 24 h early. The backtest (daily) sheds on `Action`. The GEX regime and flip themselves are unchanged (they match the reference script). When a shed starts, every pending entry/repair with a working order of the shed side is cancelled whole (`cancelShedSide`) and finalized at once, so a late fill is booked and shed in the same cycle instead of filling into the shed.
- **Direction source** (`gex_direction`, `gamma.go`): the side to avoid in a negative regime comes from the SMA trend (`sma`, default and live) or the reference script's ACCELERATION BIAS (`bias`: `BiasDir` = spot above flip × (1 + buffer) → up, below flip × (1 − buffer) → down, else neutral; positive regime = neutral). The bias in use is `StableBiasDir`: `BiasDir` must agree against the live flip and the median flip of the last `gex_bias_flip_window_minutes` (60; `GammaMonitor.recordFlip`, once per snapshot), else neutral; until the record spans the whole window (startup, or a GEX gap longer than it) the bias sheds nothing — `GammaDecision.WarmupHeld`, journaled once as a `bias_warmup` skip, `Action` still skips the side for entries and repairs (2026-10-14: a flip jump 10 min after a restart was the whole window and shed BTC's calls) — before daily expiries the script's flip jumped for 3–20 min (BTC 2026-10-12 → 72,000, 10-14 → 79,500) and the live bias shed every call with spot flat. Under `bias` the shed is `ResolveBiasAction` (bias down → puts, up → calls, confirmed on 2 snapshots), the regime-side rule, entries, top-ups and manual close read the bias, and a shed leg is re-sold by `BiasRepairBlockReason` — `gex_bias_repair_cooldown_hours` after the shed, then the bias off its side on `gex_repair_confirm_snapshots` (anchors count every snapshot in `repairIncompleteStrangles`). Both sources are always computed: journal `portfolio.sma_trend`/`gex_bias`, and `data/direction_history.jsonl` (`history.DirectionLog`, one line per change, with `other_action` = what the unused source would shed). Stress 2026-10-12: bias −16…−139 % vs sma (3–5× the sheds); live trial on BTC since 2026-10-12, ETH on sma as the control; since 2026-10-18 only stable's BTC runs bias, mvp's BTC runs sma (#168).
- **Manual rebalance** (`manualrebalance.go`): `RequestRebalance` hands the request to the Run goroutine (`rebalanceCh`), which reads fresh margin and applies `RebalanceBlockReason` — the same pure gate `applyMarginPolicy` uses, so the two never drift — then runs `runRebalance`; it skips only "limit unchanged" and `rebalanceRetryAt`. `rebalancePositions(…, dryRun)` reports every decision (`RebalanceReport`/`RebalanceAction`); with `dryRun` it works on copies of the strangles, sends nothing, journals nothing and does not re-arm. Cooldowns: 5 min per real pass (`ManualRebalanceWait`), 30 s per dry run; a refused request does not start the cooldown. Journaled `rebalance_manual`.
- **Manual close** (`manualclose.go`, pure `ManualCloseBlockReason`): the monitor may buy back a short leg at market only while `RegimeSideBlockReason` blocks its side (confirmed negative regime; puts in a bear trend, calls in a bull trend) — the leg the bot no longer sells but may still hold (2026-10-09 BTC: puts re-sold during two minutes of neutral trend). Each leg's view says whether it is allowed and what follows (`rebuilt` when it is its strangle's last leg: the slot is re-entered). The request runs on the Run goroutine (`manualCh`), re-checks the rule, records the leg like a stop (repair held by `RepairBlockReason`) and closes with `TriggerManualClose`; a request the loop has not taken within 25 s is dropped unexecuted.
- **Kill switch:** cancel all orders for the currency → read back and book what each working entry filled (`settleLeg` + `finalizePending`) → flatten at market with retries on a detached context, the book matched to the exchange's shorts before each pass (`syncBookToExchange`, no drift confirmation) and the exchange checked flat at the end → stay idle (don't exit; Docker would restart into trading). 2026-10-09: pending entries were dropped unread and 100 filled lots stayed short.
- **Startup:** reconcile from the exchange (cancel this currency's orders via `private/cancel_all_by_currency`, load positions, regroup with `GroupPositions` — an expiry may hold several strangles: calls and puts paired by size, then rank from the money; leftovers one-legged, except that an uneven pair's excess is split onto a lone leg of the other type on the same expiry, and two uneven pairs whose excesses offset (one a call too many, the other a put) are split into one more strangle (Deribit reports a strike shared by two strangles as one position; without the split, balancing bought it back and repair re-sold it at every restart — 2026-10-17 BTC 27NOV calls 2.1 + 0.2 = puts 1.8 + 0.5, #156); every position in exactly one strangle, checked with an ERROR log — and give each strangle a slot with `assignSlots` (`slotassign.go`): the slot the journal says opened its legs (`OpenSlotsFromTrades`, handed over by `RestoreStops`; a preference, never a position), else the assignment with the lowest **total** `slotScore` — closest pair first swapped ETH's two slots on a tie (2026-10-17, #156); the `reconciled` lines' `detail` gives the pairing and why the slot) → margin policy (rebalance only when the limit rests on confirmed data and nothing is frozen) → entries. **No new risk without fresh GEX** (`gexready.go`, pure `GEXWaitReason`): with GEX wired, entries (`gex_wait` skip), top-ups and repairs wait until the first snapshot and whenever it is older than `GEXStaleAfter` (5 min) — before it the regime and trend are unknown (2026-10-09: both bots sold puts seconds after a restart into a negative regime with a bear trend). Exits, balancing and the MM cut do not wait.
- **Exit thresholds bracket the entry delta:** `delta_drift_threshold` ≤ 75 % of every entry delta (`config.MaxDriftToEntryRatio`) and `delta_exit_threshold` above every entry delta — `Validate` rejects anything else, because a leg sold at a threshold is rolled or exited on the next cycle, over and over.
- **Strikes:** an entry or rebalance top-up picks its call and put together (`SelectStrikePair`): each within `delta_slippage` of the entry delta, the pair scoring | |Δc| − |Δp| | + ½ (distance of each from the target) — on a coarse grid (ETH) legs picked alone left the book tilted. A repair picks the strike nearest the entry delta (`SelectStrike`); matching it to the open leg was stress-tested and rejected (−25–30 % vs holding).
- **One expiry per slot:** a vacant slot enters `SelectSlotExpiry` (`marketdata.PickExpiry`): its window's nearest expiry unless another slot holds it (open strangle, pending entry or unconfirmed order — `heldExpiries`), then the nearest free expiry up to target × `expiry_stretch`, otherwise it waits (`no_free_expiry` skip). An empty window still waits (`no_expiry`). Rebalance complements use their own strangle's expiry. The backtest applies the same rule.
- **DTE has one definition:** `marketdata.DaysToExpiry` — whole days left, rounded down. Entry (`NearestExpiry`/`SelectExpiry`) and the exit rules (`Position.DTEAt`) both use it, so an expiry the entry accepts (DTE > `rollout_dte`) is never rolled on the next cycle. Never compute DTE another way.
- **Time:** pure functions take `now`; never call `time.Now()` inside them (the backtest replays the past).
